**Статус: готовые входные определения 11 инструментов для MVP/v0.1, согласованные с логической моделью БД.** Это точные JSON-объекты элементов массива `tools` DeepSeek; для отправки в API их объединяют в массив, выбрав инструменты разрешённого режима. Поля идентификатора пользователя и текущего контекста Python определяет по сессии, их нет в аргументах LLM.

## Источники структуры и общие правила

Поле `profile_data` соответствует [user\_profiles.profile\_data](https://arkadijgoncarov.atlassian.net/wiki/spaces/JOBRADAR/pages/1605719/Database), `criteria` — `search_contexts.criteria`. Внутренний `schema_version=1` добавляет Python, в Tool Calling не передаётся. При `create_profile` профессию принимаем отдельно; Python добавляет `profession` в профиль, без дублирования в `profile_data`. В `changes` передаются только изменяемые поля. Вложенный объект `salary` при частичном изменении обновляется по указанным ключам, а не целиком затирает оставшиеся поля. `null` допускается лишь в местах, предусмотренных моделью БД; массивы при передаче означают новое значение соответствующего списка. Неизвестные свойства отклоняются.

Набор инструментов: общий диалог — `list_profiles`, `create_profile`, `switch_context`; активный контекст — `list_profiles`, `switch_context`, `return_to_general`, `update_profile`, `list_contexts`, `create_context`, `update_context`, `search_vacancies`, `get_search_results`, `get_vacancy_details`. Дополнительная проверка полномочий выполняется в Python независимо от наличия инструмента в запросе.

## Общий контракт ответа Python → DeepSeek

Ранее утверждён единый формат результата. Для успеха обязательны `status="success"` и `data`; для ошибки обязательны `status="error"` и `error` с полями `code`, `message`, `retryable`. Содержимое data зависит от команды и описано в [реестре команд](https://arkadijgoncarov.atlassian.net/wiki/spaces/JOBRADAR/pages/2359317/Tool+Calling+v0.1). LLM видит результат в tool message; ответ пользователю строится только после получения результата.

## Реализация и проверки

Это входные схемы для LLM, не разрешение на произвольную запись в БД. Python проверяет типы, структуру, режим сессии, принадлежность сущности, допустимость операции, наличие изменений и ограничения продукта. Допустимые значения `preferences.operator`/`restrictions.operator` в БД ещё не имеют окончательно закрытого реестра, поэтому в этих схемах тип `string` без искусственно введённого enum. `salary.currency` — трёхбуквенный код ISO 4217, а фактическую допустимость проверяет приложение. Лимит выдачи `get_search_results.limit`: 1–100, по умолчанию 20 (предварительная настройка). При изменении JSONB-контрактов схемы синхронизировать с БД; сейчас дополнительных решений не требуется.
