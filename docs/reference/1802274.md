Исходные вакансии отделены от созданных LLM карточек, нормализованных тегов и персональных оценок. v0.1 не предполагает персональную блокировку компаний и вакансий.

**Уточнение:** типы приведены для целевой PostgreSQL-модели; метки «NULL (проект)» обозначают пока не утверждённые ограничения обязательности/значения по умолчанию. Для SQLite применяются совместимые физические типы.

## `vacancies`

**Назначение:** неизменённая по смыслу исходная вакансия и минимальные метаданные для идентификации и мягкого предварительного отбора без LLM. Полный текст перенесён из удаляемой vacancy\_source\_texts.

| Поле | Тип | Свойства | Назначение |
| --- | --- | --- | --- |
| `id` | BIGINT | PK | Внутренний идентификатор |
| `source` | TEXT | NOT NULL, UNIQUE pair | Платформа источника |
| `external_id` | TEXT | NOT NULL, UNIQUE pair | ID на платформе |
| `url` | TEXT | NULL | Адрес объявления |
| `title` | TEXT | NULL | Исходное название |
| `employer` | TEXT | NULL | Работодатель |
| `description` | TEXT | NULL | Полный исходный текст |
| `content_hash` | TEXT | NULL | Хеш исходного текста/значимых данных |
| `status` | TEXT | NULL | Статус доступности |
| `published_at` | TIMESTAMPTZ | NULL | Опубликована |
| `first_seen_at` | TIMESTAMPTZ | NULL | Первая встреча |
| `last_seen_at` | TIMESTAMPTZ | NULL | Последняя встреча |
| `last_checked_at` | TIMESTAMPTZ | NULL | Проверка доступности |
| `fetched_at` | TIMESTAMPTZ | NULL | Получение исходных сведений |

**Правила:** UNIQUE(source, external\_id). Collector сохраняет исходник без семантического разбора. География, зарплата, формат и стаж в нормализованном виде находятся в vacancy\_cards.

## `vacancy_cards`

**Назначение:** основная нормализованная поисковая модель, создаваемая LLM при первом содержательном анализе исходной вакансии. Карточка не хранит копию полного описания.

| Поле | Тип | Свойства | Назначение |
| --- | --- | --- | --- |
| `vacancy_id` | BIGINT | PK, FK vacancies.id | Идентификатор исходника |
| `profession` | TEXT | NULL | Нормализованная профессия |
| `specialization` | TEXT | NULL | Специализация |
| `area` | TEXT | NULL | География работы, нормализованная |
| `work_format` | TEXT | NULL | remote / hybrid / office / unknown |
| `salary_from` | NUMERIC | NULL | Зарплата от |
| `salary_to` | NUMERIC | NULL | Зарплата до |
| `salary_currency` | TEXT | NULL | Валюта |
| `experience_min` | NUMERIC | NULL | Минимальный стаж в годах |
| `summary` | TEXT | NULL | Краткое смысловое описание |
| `structured_data` | JSONB | NULL | Нестандартные условия, обязанности и подробности |
| `source_hash` | TEXT | NULL | Хеш исходных данных, по которым создана карточка |
| `extraction_version` | INTEGER | NULL | Версия промпта/процесса извлечения |
| `extracted_at` | TIMESTAMPTZ | NULL | Дата структурирования |

**Правила:** карточка создаётся/обновляется LLM за одно содержательное обращение вместе с предложением тегов и первичной оценкой для контекста. Оркестратор сохраняет универсальную карточку отдельно от персональной оценки. При актуальном source\_hash и подходящей extraction\_version карточку переиспользуют. Навыки, допуски и нормализованные требования в structured\_data не дублируются: они в tags и vacancy\_tags.

## `tags`

**Назначение:** глобальный справочник нормализованных профессиональных признаков, созданных/сопоставленных на основании результатов LLM. Не зависит от конкретного пользователя.

| Поле | Тип | Свойства | Назначение |
| --- | --- | --- | --- |
| `id` | BIGINT | PK | ID тега |
| `category` | TEXT | NOT NULL, UNIQUE pair | Категория: skill, license, education, certification и др. |
| `canonical_name` | TEXT | NOT NULL, UNIQUE pair | Единое название навыка/требования |
| `created_at` | TIMESTAMPTZ | NULL | Создание |

**Правила:** UNIQUE(category, canonical\_name). Оркестратор сопоставляет возвращённое LLM название с существующими тегами и создаёт новый только при отсутствии подходящего. Очевидные различия записи нормализуются программно; смысловые синонимы сопоставляет LLM, и подтверждённые соответствия сохраняются в tag\_aliases. Сложный классификатор синонимов не обязателен для v0.1.

## `tag_aliases`

**Назначение:** хранение подтверждённых альтернативных названий нормализованных тегов. Каждый синоним принадлежит ровно одному каноническому тегу в `tags`; повторное употребление известного синонима не требует нового обращения к LLM.

| Поле | Тип | Свойства | Назначение |
| --- | --- | --- | --- |
| `id` | BIGINT | PK | Идентификатор записи |
| `tag_id` | BIGINT | FK tags.id, NOT NULL | Канонический тег |
| `alias` | TEXT | NOT NULL | Исходный или общепринятый синоним, например Postgres |
| `normalized_alias` | TEXT | NOT NULL; индекс/ограничение однозначности уточняется | Нормализованная форма для быстрого сопоставления, например postgres |
| `created_at` | TIMESTAMPTZ | NULL (проект) | Когда синоним добавлен |

**Связи:** `tags 1:N tag_aliases`. Например, канонический тег `PostgreSQL` может иметь синонимы `Postgres`, `Postgre SQL`. `SQL` и `PostgreSQL` — связанные, но не эквивалентные понятия, поэтому не объединяются автоматически.

**Порядок разрешения нового тега:** (1) нормализуем регистр/пробелы; (2) ищем точное совпадение в `tags.canonical_name` и `tag_aliases.normalized_alias`; (3) при отсутствии ищем кандидатов и отдаём LLM на проверку смысловой эквивалентности; (4) при подтверждённом соответствии записываем новый alias к существующему tag\_id, иначе создаём новый tag; (5) связываем итоговый тег с карточкой через `vacancy_tags`.

**Ограничения:** приложение не должно автоматически сопоставлять неоднозначное имя с одним из нескольких тегов. Правило уникальности: в пределах одной категории один нормализованный синоним может ссылаться только на один канонический тег. Один тег может иметь множество разных синонимов. При совпадении с canonical\_name или синонимом другого тега той же категории сохранение блокируется до разрешения конфликта; технически индексировать normalized\_alias. Проверку обеспечивают Storage Service и ограничения/транзакции БД при реализации. Логика сохранения и проверки уникальности находится в Python, а смысловую эквивалентность при необходимости оценивает LLM. Сохранение tag\_aliases и vacancy\_tags выполняется контролируемо через Storage, не произвольным SQL от LLM.

## `vacancy_tags`

**Назначение:** требования и профессиональные признаки, извлечённые LLM для структурированной карточки. Один тег может использоваться во множестве карточек.

| Поле | Тип | Свойства | Назначение |
| --- | --- | --- | --- |
| `vacancy_id` | BIGINT | PK part 1, FK vacancy\_cards.vacancy\_id | Карточка вакансии |
| `tag_id` | BIGINT | PK part 2, FK tags.id | Нормализованный тег |
| `requirement_level` | TEXT | NOT NULL (проект) | required / optional / mentioned |
| `evidence` | TEXT | NULL | Краткий дословный фрагмент объявления, подтверждающий тег и его уровень |

**Правила:** PK(vacancy\_id, tag\_id). `required` — явно обязательное; `optional` — желательное; `mentioned` — технология, квалификация или практика лишь упомянута, в том числе в обязанностях. Evidence помогает проверить интерпретацию LLM, не участвует в поисковом индексе. FK указывает именно на `vacancy_cards.vacancy_id`. При перестроении карточки её связи с тегами обновляются согласованно.

## `context_vacancies`

**Назначение:** Актуальная оценка вакансии в конкретном поисковом контексте.

| Поле | Тип | Ключи / свойства | Смысл |
| --- | --- | --- | --- |
| `context_id` | BIGINT | PK part 1, FK search\_contexts.id | Контекст |
| `vacancy_id` | BIGINT | PK part 2, FK vacancies.id | Вакансия |
| `relevance_score` | NUMERIC | NULL | Оценка совместимости |
| `decision` | TEXT | NULL | Результат AI-анализа |
| `reasoning` | TEXT | NULL | Объяснение соответствия или несоответствия вакансии критериям и квалификации; сохраняется для повторного показа |
| `review_status` | TEXT | NULL | Резерв для реакции пользователя; без механизма блокировки в v0.1 |
| `profile_revision` | INTEGER | NULL | Редакция профиля при анализе |
| `criteria_revision` | INTEGER | NULL | Редакция критериев при анализе |
| `assessed_at` | TIMESTAMPTZ | NULL | Время оценки |

**Связи и правила:** PK(context\_id, vacancy\_id). Одна актуальная оценка для контекста; при изменении профиля или критериев её можно заменить. История версий оценок не нужна в MVP. Для явных запретов целевого MVP предпочтительно отдельное правило в criteria, но решение пока предварительное.

## Сквозной алгоритм структурирования и поиска

1. LLM формирует список поисковых направлений и синонимов, Collector находит объявления и сохраняет в vacancies.
2. Мягкий программный отбор по исходному названию, источнику и явным фактам не отбрасывает неоднозначные профессии без проверки.
3. При наличии актуальной vacancy\_cards и связей vacancy\_tags они переиспользуются.
4. Если карточки нет/она устарела, LLM получает полное описание и доступные исходные метаданные и в одном вызове возвращает универсальную карточку, перечень тегов с уровнями/evidence и предварительную оценку относительно текущего контекста.
5. Оркестратор проверяет контракт, сопоставляет теги со справочником, сохраняет vacancy\_cards и vacancy\_tags, а персональную оценку — в context\_vacancies.
6. Повторный локальный поиск выполняется по колонкам vacancy\_cards и индексированным связям tags/vacancy\_tags с JOIN к vacancies; для других контекстов LLM не структурирует актуальную карточку повторно.

**Не входят в v0.1:** блокировка конкретных компаний/вакансий, массовая система синонимов, автоматическое постоянное фоновое переизвлечение карточек.

## Уточнение актуальности вакансий и персональной оценки

`reasoning` хранится в `context_vacancies` вместе с оценкой. При изменении профиля или критериев пересчитывается персональная оценка по уже сохранённой актуальной карточке, без нового запроса на сайт и без повторного извлечения карточки. Для нового поискового контекста оценка вычисляется по существующей карточке. Карточка считается актуальной относительно последнего сохранённого текста: сверка `vacancy_cards.source_hash` с `vacancies.content_hash` и `extraction_version`. Постоянной перепроверки HH.ru нет, изменения на сайте до следующего получения текста неизвестны. Перед будущей функцией отклика предусмотреть возможность точечной проверки существования и содержимого вакансии; отклики сейчас не реализуются.
