Единый поток сообщений и сохраняемая история каждого запуска поиска. Для v0.1 нет отдельного постоянного хранилища ожидающих подтверждений.

**Уточнение:** типы приведены для целевой PostgreSQL-модели; метки «NULL (проект)» обозначают пока не утверждённые ограничения обязательности/значения по умолчанию. Для SQLite применяются совместимые физические типы.

## `messages`

**Назначение:** Сообщения единого общего чата. Контекстная принадлежность — метаданные, не отдельные чаты.

| Поле | Тип | Ключи / свойства | Смысл |
| --- | --- | --- | --- |
| `id` | BIGINT | PK | ID сообщения |
| `user_id` | BIGINT | FK users.id, NOT NULL | Владелец |
| `session_id` | BIGINT | FK user\_sessions.id, NOT NULL | Сессия |
| `context_id` | BIGINT | FK search\_contexts.id, NULL | NULL — общий диалог; иначе связанный контекст |
| `role` | TEXT | NULL (проект) | user / assistant / tool (перечень уточнить) |
| `content` | TEXT | NULL (проект) | Текст сообщения |
| `created_at` | TIMESTAMPTZ | NULL (проект) | Дата |

**Связи и правила:** Одна хронология в интерфейсе; переключения обсуждаются текстом. Не каждый ответ обязательно принадлежит контексту. Проверять принадлежность session\_id и context\_id одному пользователю.

## `search_tasks`

**Назначение:** Конкретный запуск поиска для одного поискового контекста.

| Поле | Тип | Ключи / свойства | Смысл |
| --- | --- | --- | --- |
| `id` | BIGINT | PK | ID запуска |
| `context_id` | BIGINT | FK search\_contexts.id, NOT NULL | Поисковый контекст |
| `goal` | TEXT | NULL (проект) | Задача от пользователя |
| `state` | TEXT | NULL (проект) | pending/running/completed/failed/cancelled |
| `search_queries` | JSONB | NULL (проект) | Сформированные запросы |
| `target_count` | INTEGER | NULL (проект) | Целевое количество обработки в задаче; не путать с лимитами сбора/LLM и количеством показанных вакансий |
| `is_partial` | BOOLEAN | NOT NULL, DEFAULT false (проект) | Признак частичного завершения поиска |
| `stop_reason` | TEXT | NULL | Причина неполного завершения (например, лимит, таймаут, CAPTCHA, сбой источника) |
| `created_at` | TIMESTAMPTZ | NULL (проект) | Создан |
| `completed_at` | TIMESTAMPTZ | NULL | Завершён |

**Связи и правила:** Множество задач может принадлежать одному контексту. Задание не привязывать к одной сессии как к единственному владельцу данных.

**Общие правила JSONB:** версия контракта явно обозначается в JSON; имена свойств и enum — английские, пояснения и пользовательские значения могут быть русскими. `null` означает неизвестное/не указано, пустой массив — отсутствуют извлечённые элементы (не доказательство отсутствия требований). Отсутствующий необязательный ключ допускается, но приложение нормализует его согласно контракту. Оркестратор валидирует типы и значения перед сохранением. Внутренние версии редактирования `revision`/`criteria_revision` не являются версиями JSON-контракта.

### Контракт JSONB: `search_tasks.search_queries`

| JSON-путь | Тип | Обязательность | Описание |
| --- | --- | --- | --- |
| `version` | integer | Да | Версия контракта поискового задания |
| `queries[]` | object\[\] | Да | Один или более запросов в рамках запуска |
| `queries[].source` | string | Да | Код платформы: hh, другой подключённый источник |
| `queries[].text` | string | Да | Текстовый поисковый запрос |
| `queries[].areas[]` | string\[\] | Нет | Географические параметры для источника |
| `queries[].filters` | object | Нет | Технические фильтры источника; ключи зависят от адаптера платформы |
| `queries[].priority` | integer | Нет | Очередность обработки, меньше — раньше |

**Правила:** Фиксирует снимок фактически сформированных поисковых запросов, не заменяет search\_contexts.criteria. filters зависит от адаптера источника, но каждый поддерживаемый адаптер должен иметь собственную проверяемую схему. Неизвестные фильтры нельзя молча считать применёнными.

**Пример JSON**

```
{
  "version": 1,
  "queries": [
    {
      "source": "hh",
      "text": "Системный аналитик",
      "areas": [
        "Россия"
      ],
      "filters": {
        "work_format": "remote"
      },
      "priority": 1
    },
    {
      "source": "hh",
      "text": "IT-аналитик",
      "areas": [
        "Россия"
      ],
      "filters": {},
      "priority": 2
    }
  ]
}
```

## `task_vacancies`

**Назначение:** Состав вакансий, найденных или выбранных в рамках конкретной поисковой задачи.

| Поле | Тип | Ключи / свойства | Смысл |
| --- | --- | --- | --- |
| `task_id` | BIGINT | PK part 1, FK search\_tasks.id, NOT NULL | Поисковая задача |
| `vacancy_id` | BIGINT | PK part 2, FK vacancies.id, NOT NULL | Вакансия |
| `origin` | TEXT | NULL (проект) | Источник включения: новый сбор либо локальная БД; значения уточнить |

**Связи и правила:** Составной PK (task\_id, vacancy\_id). Одна вакансия может участвовать в нескольких поисках. Отличать список найденных задачей объявлений от контекстных оценок в context\_vacancies.

[Вернуться к общей ERD](https://arkadijgoncarov.atlassian.net/wiki/spaces/JOBRADAR/pages/1605696/Database+JobRadar)

**Частичный результат:** при наличии сохранённых результатов после неполной обработки допустим `state=completed` с `is_partial=true` и заполненным `stop_reason`. При полном успешном завершении `is_partial=false`, `stop_reason=NULL`. Если результат отсутствует вследствие сбоя, `state=failed` (либо cancelled при явной отмене). Приложение уведомляет пользователя о частичном результате.
