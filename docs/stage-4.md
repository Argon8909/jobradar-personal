# JobRadar v0.1 — Flask-чат

## Реализовано

- Фабрика приложения `web/app.py` подключает готовый Orchestrator; бизнес-логика
  и DeepSeek остаются в своих модулях. Команда запуска: `python -m jobradar serve`.
- Браузерный чат на русском: единая хронология, список профилей/контекстов,
  индикация текущего контекста, пустое состояние с подсказками, ожидание ответа,
  отправка по Enter и перенос строки по Shift + Enter. Выбор контекста — через диалог,
  без отдельных переключающих вкладок или кнопок изменения профиля.
- История доступна порциями по 50 записей; подгрузка сохраняет положение прокрутки.
  Пользователь видит только текстовые сообщения, без tool IDs, аргументов и протокола.
- Адаптивные стили для настольного и узкого экрана, без внешних CDN или шрифтов.
- Ответ/ошибка приложения не сбрасывает сохранённые профили или контексты.
  При сетевом сбое текст ввода сохраняется; автоматического повтора команды нет.
  Кнопка обновления позволяет проверить сохранённую историю перед повторной отправкой.

## Сессия и локальный запуск

Приложение работает для локального пользователя id=1. ID сессии задаётся сервером
и хранится в подписанной HttpOnly/SameSite cookie; в аргументах API нет выбора
пользователя или session_id. Cookie сохраняется после закрытия браузера в пределах
срока действия Flask-сессии. Подпись сохраняется в игнорируемом `.env` как
JOBRADAR_SESSION_SECRET (генерируется автоматически). Ключ DeepSeek не меняется.
Перезапуск Flask восстанавливает историю и активный контекст; неподтверждённые
предложения из памяти процесса не восстанавливают разрешение на действие.

POST проверяет CSRF-token, Origin при его наличии и входной JSON. Скрипты/HTML
из пользовательских или LLM-сообщений отображаются только как текст. Ответы не
кэшируются, внешние ресурсы не подключаются. Flask требует версию >=3.1 для
проверки TRUSTED_HOSTS; serve допускает только loopback-адрес и отключает debug/reloader.

Поиск остаётся синхронным предметным сервисом; фоновые очереди не добавлены.
Пока модель отвечает, интерфейс показывает ожидание. Второй одновременный POST
получает CHAT_BUSY, а не создаёт второй ход в очереди. Существующий оркестратор
переиспользуется для сессии, поэтому согласие на предложение работает между HTTP-запросами.

Схема БД, системные промпты и предметные контракты инструментов не менялись.
Новая `public_page` читает существующую таблицу messages с фильтром владельца.

## Проверки

- 78 тестов v0.1: включая Flask API, реальные сервисы и временную SQLite.
- 3 браузерных теста Playwright в Chromium: создание профиля и восстановление
  после обновления, мобильный экран/клавиатура/безопасное отображение HTML,
  сетевой сбой с сохранением ввода и обновлением истории.
- 9 регрессионных тестов v2.2.
- Проверены восстановление cookie в новом экземпляре приложения, постраничная
  история, изоляция пользователей, некорректные запросы, CSRF/Origin/Host и занятый чат.
- Просмотрены скриншоты настольной и мобильной версий; отсутствуют горизонтальный
  скролл и ошибки JavaScript. Зависимости и git diff --check проверены.

Все проверки выполнены на Linux/Python 3.12 с подставными ответами LLM.
Запросы к платному DeepSeek API и HH.ru не выполнялись; проверка под Windows
и реальный диалог с ключом остаются практической проверкой на пользовательском ПК.
