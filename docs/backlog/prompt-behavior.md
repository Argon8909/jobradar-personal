# Следующая итерация: управляющие промпты и широта поиска

Статус: запланировано, не реализовано. Зафиксировано по просьбе пользователя
18 ноября 2026 года. В этой задаче сейчас сохраняется задание; действующие промпты
и поведение приложения не меняются. При планировании следующей итерации включить
это задание в работу.

Задание включено в начальную [концепцию v0.2](../v0.2-concept.md).
Статус остаётся запланированным; включение в концепцию не означает реализации.

## Наблюдение и цель

Пользователь тестирует первоначальную сборку, до обновлений подтверждений и
диагностики. В присланном диалоге поиск № 5 нашёл 35 вакансий, оценил 4 и остановился
на лимите новых анализов после ошибок. В выдаче преобладают системные аналитики.
Ассистент предлагает создать контекст «ИИ и автоматизация» с подробными критериями.
На вопрос «почему ищешь только по названию системный аналитик?» он повторяет
предложение создать контекст, теперь только с названием, без объяснения поиска.

Подтверждены уход от ответа и потеря критериев в повторном предложении.
Единственный поисковый запрос по названию профессии этим фрагментом не доказан:
нужно проверить сохранённый search_queries и порядок обработки. Возможны как
узкий план, так и исчерпание бюджета до перехода к другим запросам.

Цель: поиск по навыкам, задачам и допустимым смежным ролям внутри выбранного
контекста; понятное объяснение действий; отсутствие навязанного дробления на
профили/контексты для каждого нового названия должности.

## Требуемое поведение

1. Различать профессиональный профиль (фактическая квалификация), поисковый
   контекст (направление и условия подбора) и поисковые запросы к источнику.
   Новое ключевое слово или смежное направление сами по себе не требуют нового
   профиля либо контекста. Несколько направлений допустимы в одном контексте.
2. При наличии подходящего профиля использовать его факты для поиска смежных
   ролей. Например, системный анализ, API и интеграции могут служить основанием
   рассматривать релевантные задачи AI-автоматизации. Не приписывать пользователю
   опыт с AI, конкретными инструментами или уровень квалификации, которого он
   не сообщал. Желание перейти в направление не считать подтверждённым опытом.
3. Отдельный контекст предлагать как возможность вести самостоятельный поиск
   с другими условиями, а отдельный профиль — при самостоятельной квалификации
   или по выбору пользователя. Не делать создание обязательным условием
   расширения существующего поиска. Уважать явное желание пользователя разделить их.
4. Планировщик учитывает основные и смежные названия ролей, специализации,
   компетенции и характер задач. При явно широком запросе формирует несколько
   содержательно разных вариантов, не сводит всё к profession или его повторениям.
   Если пользователь явно ограничил поиск одной ролью, не расширять его вопреки
   ограничению. Нерелевантные названия ради количества не добавлять.
5. Различать объяснение прошлого поиска, разовое расширение следующего поиска
   и сохранение новых критериев. Вопрос «почему?» не является согласием создать
   сущность, изменить критерии, переключиться или начать новый поиск. Сначала
   отвечать на заданный вопрос по фактическому плану и диагностике. Если сведений
   нет, прямо сообщать об этом, не выдумывать выполненные запросы.
6. Разовый запрос «найди ещё варианты в AI-автоматизации» не должен автоматически
   переписывать профиль/критерии. Явное поручение сохранить направление выполняется
   через существующие инструменты и правила авторизации. Согласие повторно не
   запрашивается, когда явная команда уже достаточна.
7. Не зацикливаться на «Создать контекст? Подтверждаете?» после уточнения или
   вопроса пользователя. Для действующего предложения сохранять полный набор
   аргументов; не подменять предложение с критериями вариантом только с названием.
   После смены намерения старое предложение не исполнять по случайному «да».

## Область доработки

- Пересмотреть согласованно `prompts/dialogue.md` и `prompts/search_planner.md`,
  а также технические инструкции распознавания намерения/предложения в
  `src/jobradar/dialogue/agent.py`. Основное правило широты уже есть в Planner:
  «Не ограничивай поиск только точным названием профессии». Нужно обеспечить
  его применение и согласованность управляющих инструкций.
- Перед правками проверить актуальное состояние репозитория: исправления
  подтверждений и диагностики уже опубликованы. Прогнать этот сценарий на новой
  сборке, не считать поведение старой сборки автоматически воспроизводимым в ней.
- Использовать существующий сохранённый план запросов и диагностику для
  объяснения охвата. Проверить, не расходуется ли весь бюджет на первый запрос.
  Если причина в очередности/лимитах исполнения, оформить связанную техническую
  доработку; один текст промпта не гарантирует исправление этой причины.
- Оформить новую версию управляющих промптов и описать отличие от v1.0,
  согласовать источник истины с документацией Confluence при реализации.
  Сохранить границы v0.1, существующие права, логическую схему и 11 команд.
  Данные HH получать только через Playwright. Визуальная диагностика — отдельная задача.

## Критерии приёмки следующей итерации

| Сценарий | Ожидаемый результат |
|---|---|
| Существующий профиль системного аналитика; «Найди также работу с интеграциями и AI-автоматизацией» | Используется существующий профиль/контекст; несколько обоснованных поисковых вариантов; нет обязательного создания сущностей и выдуманного AI-опыта |
| «Почему ищешь только по названию системный аналитик?» | Объяснение фактического плана, охвата и ограничений либо честное отсутствие данных; без нового поиска и предложения подтвердить создание контекста |
| После предложения создать контекст с критериями пользователь задаёт вопрос о поиске | Ответ на вопрос; критерии не теряются и никакое создание не выполняется |
| Пользователь подтверждает актуальное полное предложение коротким «да» | Выполняются именно показанные аргументы; профиль/критерии моделью заново не сочиняются |
| «Найди разово вакансии по автоматизации» | Разовая задача, сохранённые данные профиля и контекста не меняются |
| «Добавь AI-автоматизацию в направления моего текущего поиска» | Изменяются направления текущего контекста по явной команде, без навязывания нового профиля |
| «Создай отдельный контекст для AI-автоматизации» | Создаётся и активируется отдельный контекст существующего профиля по действующим правилам |
| «Ищи только системных аналитиков, смежные роли не нужны» | Явное ограничение соблюдается |
| Первый запрос исчерпал бюджет до остальных | Ответ сообщает неполный охват; не утверждает, что все направления проверены |

Проверить как минимум сохранность аргументов/данных и отсутствие лишних действий
автоматическими сценариями. Отдельно оценить качество реальных ответов модели на
этих репликах: тест с заранее заданным ответом LLM сам по себе не доказывает,
что новая формулировка промпта исправила поведение.
