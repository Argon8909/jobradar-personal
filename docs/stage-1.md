# JobRadar v0.1: первый этап

Основа: `jobradar-v2.2`, commit `ece055af3eb1f68537e35771470d6cbb09029807`.
Ветка реализации: `jobradar-v0.1`. Старая база не переносится.

## Готово

- Python-пакет `src/jobradar` с границами компонентов модульного монолита.
- Публичная конфигурация `config/v0.1.json`: предварительные лимиты из Confluence,
  отдельный путь новой БД, таймауты, параметры DeepSeek и локального UI.
- Четыре исходных системных промпта версии 1.0 в `prompts/`, без изменения текста.
- SQLite: все 14 таблиц актуальной ERD, внешние ключи, составные ключи,
  дедупликация `(source, external_id)`, связь тегов с карточкой,
  `reasoning`, `is_partial`, `stop_reason`.
- Атомарное создание схемы, идемпотентная инициализация, один локальный
  пользователь, явная граница транзакции. Инициализация чужой/старой схемы запрещена.
- CLI `python -m jobradar init-db --config config/v0.1.json`.
- Офлайн-тесты конфигурации, связей, ограничений, сохранения и отката.

Исходные документы и их версии сохранены в `docs/reference/`; источники перечислены
в `docs/reference/sources.json`. Это снимок основания реализации, а не альтернативная
нормативная документация. Текст ERD обновлён по актуальной странице модели.

## Физическая адаптация SQLite

- BIGINT PK → INTEGER PRIMARY KEY; JSONB → TEXT с проверкой валидного JSON-объекта;
  BOOLEAN → INTEGER 0/1; NUMERIC сохранён; время → TEXT ISO 8601 UTC.
- Предметные поля не добавлялись. Версия схемы и идентификатор приложения хранятся
  в SQLite PRAGMA, а не в дополнительной таблице.
- На каждом соединении включены внешние ключи и настроен busy timeout.
- SQL не задаёт неподтверждённую шкалу `relevance_score` и enum `decision`.
  Значения origin/status/role, для которых реестр ещё не утверждён, остаются TEXT.
- Уникальность нормализованного синонима внутри категории обеспечивается индексом
  и триггерами, связывающими `tag_aliases` с категорией в `tags`.
  Новая колонка category не вводится. Все пишущие соединения должны открываться
  через Database: он регистрирует normalize_tag (casefold + нормализация пробелов).
- Удаления не каскадируются: SQLite запрещает удалять связанные строки.
  Правило последнего контекста, проверка владельца, глубокая проверка JSON по
  предметным схемам и автоматическая активация относятся к сервисам следующего этапа.

## Граница этапа

Проверки в среде Linux, Python 3.12:

- `python -m unittest discover -s tests/v01 -v` — 21 тест успешно.
- `python -m unittest discover -s tests -v` — 9 регрессионных тестов v2.2 успешно.
- `python -m pip check` — конфликтов зависимостей нет.
- `git diff --check` — ошибок форматирования нет.
- Все четыре файла промптов побайтово по тексту совпали с блоками исходной страницы.
- Команда init-db выполнена с основной конфигурацией; создана новая локальная БД.

Windows-инструкция подготовлена, но непосредственно на Windows тесты не выполнялись.
Реальные запросы HH.ru/DeepSeek и запуск браузера в первый этап не входят.

Пакеты orchestration, dialogue, llm, tools, profiles, search, sources, analysis и web
пока обозначают структуру, а не работающие компоненты. Не реализованы диалог,
11 обработчиков команд, поиск HH.ru, анализ DeepSeek или новый Flask-чат.
Старые корневые модули v2.2 оставлены без изменений и не импортируются новым пакетом.
`requirements.txt` относится к старому прототипу; зависимости новой реализации
определены в `pyproject.toml`. PDF-импорт не добавлен в зависимости новой версии.

В новом задании есть разрешение обходить CAPTCHA, противоречащее прежнему заданию.
На первом этапе это ни на что не влияет: сетевой сбор не выполняется. Обход CAPTCHA
не реализован. При блокировке источника документация предусматривает частичный
результат с stop_reason либо failed при отсутствии результатов.
