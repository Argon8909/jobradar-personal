# JobRadar Agent v2.2 — локальный прототип

Обновление с v2.1. Backend: Python/Flask, Playwright/HH, DeepSeek Tool Calling, SQLite.

## Что изменилось

- **Обязательный итоговый отчёт:** после окончания фонового поиска автоматически появляется сообщение в чате: число оценённых вакансий, недостигнутая цель (если применимо), названия, категории, причины, ссылки. Для этого не нужен дополнительный вопрос и не нужен второй API-запрос. Отчёт публикуется также при ошибке или ручной остановке, если есть результаты.
- **База прежде HH:** поиск сначала отбирает кандидатов из SQLite по названию, карточке/тегам, а для неразмеченных записей — по описанию. Затем выполняется хотя бы один запрос к HH для проверки свежих результатов. SQL-выборка ограничена; вся БД не отправляется DeepSeek.
- **Универсальные AI-карточки:** для ещё не размеченной вакансии один запрос DeepSeek возвращает `card` (профессия, специализация, навыки, сертификаты, условия, обязательные/желательные требования, краткое описание) и отдельно `analysis` (персональная оценка). Карточка сохраняется в `vacancy_cards`, оценка в `analyses`.
- **Дедупликация:** проверка ID по всей SQLite-базе, а не по последним 2000. Результаты конкретной задачи сохраняются в `task_vacancies`.
- **Контроль количества:** число «изучи 20 вакансий» передаётся как цель; при лимите ниже цели это честно указано в отчёте. Повторный поиск не обещает гарантировать нужное число, если выдача исчерпана.
- **Повторные оценки:** при изменении профессионального профиля кешированная персональная оценка не считается действительной и пересчитывается.
- **Устойчивость API:** один повтор для генерации, обрезанной `max_tokens` (включая JSON классификатора).
- Исправления v2.1 по прокрутке чата (Enter / Shift+Enter), Tool Calling и загрузке резюме сохранены.

## Обновление существующей установки (Windows CMD)

1. **Остановите** старый `py app.py` (Ctrl+C).
2. **Сделайте резервную копию** папки JobRadar, особенно `jobradar.db`, `.env`, `config.json`, `browser_profile/`.
3. Распакуйте ZIP **в ту же папку**, с заменой файлов приложения (`app.py`, `orchestrator.py`, `storage.py`, `deepseek.py`, `toolspec.py`, `collector.py`, `templates/index.html`, `README.md`, `tests/`). **Не удаляйте** `jobradar.db`, `.env`, `browser_profile/`, `vacancies.json` и другие данные. Архив их не содержит.
4. Установите зависимости при необходимости: `py -m pip install -r requirements.txt`.
5. Запустите `py app.py`, откройте `http://127.0.0.1:8765`, обновите через Ctrl+F5.
6. Для проверки попросите: «Найди вакансии на стыке системного анализа и AI, изучи 20 штук».

Для чистой установки создайте `.env` из `.env.example` с `DEEPSEEK_API_KEY`, а конфигурация по умолчанию — в `config.json`.

## Что ещё не сделано

- Это **SQLite**, PostgreSQL и многопользовательский режим ещё не подключены.
- Поиск по базе — **начальный гибридный SQL LIKE по карточкам, названиям и неразмеченным описаниям**, не полнотекстовый индекс PostgreSQL и не эмбеддинги. Для небольшого каталога нормально; для сотен тысяч записей потребуется индексирование.
- Исходный текст вакансии пока сохраняется в `vacancies.data` для последующей переклассификации. Универсальная карточка хранится отдельно и используется для поиска. Перенос оригинала в отдельный сжатый архив или политика удаления — отдельная миграция.
- Старые записи с прежними `analyses` без карточек будут размечаться по мере попадания в новый поиск/анализ, что потребляет токены.
- Фоновый поиск пока живёт **в процессе Flask**. При выключении ПК или остановке приложения поиск прервётся, однако база и завершённые результаты сохранятся.
- Полученные из локальной базы вакансии могут оказаться закрытыми: нет надёжной независимой проверки актуальности при каждой выдаче. Отчёт маркирует их соответствующим образом.
- Массовый мониторинг, Авито, Хабр, VK и PostgreSQL — будущие этапы. Соблюдайте правила площадок для автоматизированного сбора.
- Реальные запросы к HH/DeepSeek **не выполнялись в офлайн-тестах** — проверьте на своём аккаунте с локальным ключом.

## Офлайн-тесты

`py -m unittest discover -s tests -v`

## Безопасность

Flask слушает только `127.0.0.1:8765`. **Не публикуйте** этот интерфейс без авторизации и защиты. API-ключ храните только в локальном `.env`. Не добавляйте `.env`, `jobradar.db`, `browser_profile/` в Git.
