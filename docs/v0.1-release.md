# JobRadar v0.1 — итог реализации

Код технического прототипа завершён в ветке jobradar-v0.1 на основе v2.2
ece055af3eb1f68537e35771470d6cbb09029807. Старая ветка и данные не менялись.
Последнее указание пользователя отменило остановки для согласования промежуточных этапов.

## Реализованный объём

- Модульный монолит: небольшая точка композиции, предметные сервисы,
  общий контракт источников, явный реестр обработчиков, SQLite Storage.
- Один локальный пользователь, несколько профилей и контекстов. Создание и
  активация атомарны; обновления частичные; проверяются владелец, режим и редакции.
- DeepSeek Client, Dialogue Agent и все 11 обработчиков утверждённых команд.
  Нет произвольного SQL или инструментов сохранения тегов у LLM.
- HH.ru через Playwright: поиск, пагинация, полный исходник с метаданными,
  география, форматы работы, отдельный браузерный профиль, ручной hh-login.
- Search Planner; один структурированный проход для новой карточки/тегов/оценки;
  Tag Resolver с сохранением синонимов и отказом от неоднозначного объединения.
- Поиск сначала по ограниченной выборке SQLite, затем обращение к источнику.
  Дедупликация по source/external_id, независимый состав каждой задачи.
- Переиспользование карточек по хешу и версии, повторная оценка по новым условиям
  без повторного извлечения и без запроса сайта при чтении сохранённых результатов.
- Синхронные задачи с лимитами, статусом, сохранением частичных результатов и
  восстановлением прерванных задач после перезапуска. Финальный отчёт с причинами/ссылками
  формируется Python, поэтому не теряется при сбое последующего ответа DeepSeek.
- Flask-чат: история, текущий контекст, поток статусов и результата, безопасные ссылки,
  адаптивная страница и восстановление cookie/сессии.
- Минимальные структурированные логи задач/LLM, без резюме, переписки и ключей.

Системные промпты 1.0, входные JSON Schema и логическая модель БД сохранены.
Выходные технические схемы основаны на существующих полях, без расширения ERD.
[Контракты](contracts/README.md), [инструкция запуска](../README.md).

## Проверки

- 112 тестов v0.1 с реальными временными SQLite-файлами и подставными сетевыми границами.
- 5 браузерных тестов Playwright/Chromium: интерфейс, восстановление, мобильная клавиатура,
  отображение недоверенного текста, разрыв сети, HH-парсер, потоковый поиск и кликабельная ссылка.
- 9 регрессионных тестов старого прототипа.
- Сборка wheel и наличие модулей, SQL, JSON Schema, HTML/CSS/JS в пакете.
- Проверки зависимостей, компиляции Python и git diff --check.

Отдельный сквозной приёмочный тест выполняет: профиль аналитика → дополнительный
контекст удалённой работы → поиск → свободная обратная связь/обновление критериев →
повторный поиск без нового извлечения → общий диалог → профиль водителя с категорией B →
поиск по второму профилю → возврат к первому контексту → новый экземпляр Flask с сохранением
профилей, условий, истории и активного контекста. Весь путь идёт через HTTP,
Dialogue Agent, Dispatcher, Search Manager и SQLite; подставлены только ответы LLM/источника.

Проверены CAPTCHA после первого результата, отсутствие результатов, сбой LLM на одной
вакансии, лимиты сбора/анализа/LLM, просроченный дедлайн, атомарный откат карточки и тегов,
изменение исходника, синонимы/неоднозначности, доступ к чужой задаче и закрытие HTTP-потока.
Событие «Поиск запущен» проверено до первого Planner/Source/Analyzer-вызова.

## Практические ограничения проверки

Тестовая среда — Linux/Python 3.12. Windows-инструкция подготовлена, но запуск на
реальном Windows здесь не выполнялся. Пользовательский ключ DeepSeek не запрашивался;
платные API-вызовы не делались. Качество интерпретации живой моделью требует проверки
с локальным ключом, доступной моделью и реальными пользовательскими фразами.

Проба реального HH.ru в изолированном браузерном профиле (не более одной вакансии)
не смогла прочитать сайт. Отдельная диагностика установила:
`Page.goto: net::ERR_CERT_AUTHORITY_INVALID at https://hh.ru/`.
В облачном Chromium нет нужного доверия к TLS-сертификату; проверка сертификатов
не отключалась. Поэтому живая разметка HH и полный цикл с реальными внешними сервисами
не подтверждены этим прогоном. SourceAdapter сообщает SOURCE_TLS, а не выдаёт вымышленные данные.

Для практического запуска: установите Chromium, заполните локальный .env, при необходимости
выполните hh-login и запустите serve. При CAPTCHA сбор останавливается; пользователь
может выполнить проверку вручную. Постоянной проверки свежести объявлений нет.

## Границы версии

Нет автооткликов, мониторинга, Авито, Redis/Celery/Docker, полноценной плагинной платформы,
постоянных блокировок компаний/вакансий, миграции старой БД или новых продуктовых правил.
Ранее отложенные функции не требуются для завершения технического v0.1.
