# Отдельная диагностика и управляющие промпты v1.1

Исправления текущей v0.1 по результатам поиска № 7 пользователя. Redis,
PostgreSQL, vision и мессенджеры остаются отдельной работой v0.2.

## Панель

`/diagnostics` — самостоятельная страница, открывается из чата в другой вкладке.
Она использует существующую сессию и активный контекст. Доступны последние
100 поисков контекста, выбор конкретного или автоматическое наблюдение последнего,
сводка, даты, план запросов и география, неоценённые вакансии, события с фильтрами
по уровню и тексту (код/этап/ID), вызовы LLM и ручной экспорт JSON.
Обновление каждые три секунды можно отключить. Чтение панели не ждёт окончания
синхронного поиска; файл читается после атомарной замены, доступ к задаче проверяется
по БД и активному контексту. Общая логическая схема БД не менялась.

Коды ошибок, JSON Pointer, исходные ответы, предупреждения тегов и подробные
причины не добавляются в новые сообщения чата и ответы поисковых инструментов
для диалогового LLM. В чате остаются результаты, общий статус, вопросы о критериях
и действие человека при проверке HH. Существующая переписка не удаляется и
не переписывается: старые сообщения с диагностикой сохраняются в истории.

Панель — представление существующих сервисов и API, не часть текста общения.
Это граница для будущего отдельного диагностического инструмента, а не новый
Tool Calling-инструмент среди утверждённых 11 команд.

## Что записывается

Для каждого специализированного обращения Search Planner, Vacancy Analyzer,
Tag Resolver: ID вызова/вакансии, модель и параметры, хеш системного промпта,
время, длительность, номер попытки, признак исправления, результат, usage и
finish_reason при наличии. Ошибка JSON дополнена строкой/колонкой/позицией;
ошибка схемы — правилом, путём, ожидаемым значением правила и объяснением валидатора.
Предупреждение по неверному тегу содержит сам тег для анализа причины пропуска.

Настройки в `config/v0.1.json`:

| Настройка | По умолчанию | Значение |
|---|---|---|
| diagnostics.capture_llm | errors | off/errors/all — сохранение тел ответов |
| diagnostics.retention_days | 7 | Срок хранения локальных журналов |
| diagnostics.max_response_chars | 65536 | Максимум символов тела ответа и снимка входа |
| diagnostics.max_file_bytes | 5242880 | Порог удаления тел старых вызовов из файла |

При errors сохраняются запрос, промпт, схема и тело ошибки, а также ответ на
исправление, даже если оно успешно. При all — тела всех специализированных
ответов. При off — метаданные и описание проверки, без тел/снимка запроса.
Обрезка текста и удаление тел по размеру помечаются в журнале. Сохранение
не должно отменять результат поиска при недоступном диске. Старые файлы
очищаются при начале нового поиска; это не фоновая служба.

Известные поля секретов и конструкции Authorization/Bearer маскируются, заголовки
API не записываются. Маскирование не гарантирует удаления всех произвольных
секретов в свободном тексте. Файлы могут содержать персональные данные профиля
и вакансий, находятся в игнорируемом data/ и не отправляются автоматически.
Перед ручной передачей экспорта проверить содержимое. Консоль получает только
краткие метаданные, не тела запросов и ответов. Логирование свободного диалога
и всех его вызовов в этот журнал поиска не включено.

## Промпты и география

Изменены dialogue.md, search_planner.md, vacancy_analyzer.md. Версия изменений —
v1.1 относительно сохранённых исходников v1.0 в docs/reference/2293817.md.
Confluence этим коммитом не обновляется. Входные определения 11 команд и
постоянные бизнес-поля карточки не изменены. Обновлён экспорт технической
выходной схемы Planner в docs/contracts/llm-outputs.json.

- Различаются квалификация, критерии и разовый запрос. Смежное направление
  само по себе не требует нового профиля/контекста; вопрос не считается согласием.
- Географическая группа не передаётся как название региона HH или ключевое
  слово профессии. Planner может вернуть конкретные страны через
  resolved_locations, с объяснением. Исходное широкое условие сохраняется.
  Без достаточных оснований приложение спрашивает страны до запуска браузера.
  Единственный обязательный список «ближнего зарубежья» не навязывается.
- Analyzer получил явную форму card/structured_data/tags/assessment и минимальный
  пример JSON. Это не отменяет строгую проверку и ограниченную попытку исправления.

Нельзя считать, что обновление промпта гарантирует качество живой модели.
Автоматические сценарии проверяют границы, сохранность данных, схему и переходы;
качество интерпретации реальных реплик нужно проверить с пользовательским ключом.

## Обновление

Остановить сервер Ctrl+C, получить свежую jobradar-v0.1, активировать окружение,
выполнить python -m pip install -e . и запустить python -m jobradar serve --config
config/v0.1.json. Не удалять .env и data/. Обновить страницу Ctrl+F5.
Для новой диагностики нужен новый поиск: исторические ответы LLM восстановить нельзя.

Проверено: 141 основной тест, 11 браузерных сценариев Chromium (включая отдельную
панель, безопасное отображение ответа и скачивание JSON), 9 тестов предыдущего
прототипа. Зависимости: pip check без конфликтов. Проверки модели и источника
используют контролируемые ответы; живые DeepSeek/HH здесь не проверены.
