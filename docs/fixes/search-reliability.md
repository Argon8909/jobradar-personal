# Надёжность поиска v0.1

Исправления касаются потерь результатов и непрозрачного «Не оценена» при работе
через HH.ru/Playwright. Модуль визуальной диагностики, скриншоты, vision-модель и
отправка в мессенджеры сюда не входят.

## Что изменено

- Для каждой ошибки анализа сохраняются ID вакансии, этап, код, безопасное
  сообщение, путь поля JSON и правило проверки, если применимы. Не записываются
  исходный ответ модели, резюме, текст объявления, ключи, cookies.
- Ошибка JSON/основной структуры допускает одно исправление. Общий лимит
  LLM-вызовов и дедлайн остаются прежними. HTTP-ошибки/обрезанный ответ отдельно
  классифицируются; бесконечных повторов нет.
- Тег проверяется независимо от карточки/оценки. Цитата допускает лишь различия
  пробелов/переносов строк, сохраняется реальный исходный фрагмент. Выдуманная
  цитата, некорректный тег, неизвестный ID или отказ Resolver пропускают этот тег.
- Попытки нового анализа, успехи, ошибки, повторное использование, переоценки,
  исправления ответа, предупреждения тегов и ошибки источника считаются отдельно.
  Повторное обнаружение той же версии неудачно обработанной вакансии внутри
  задачи не запускает повторный анализ. Изменившийся текст можно анализировать заново.
- На HH ожидается загрузка описания. Резерв — JobPosting JSON-LD из DOM страницы,
  без запросов API. Ошибка одной детали выдаёт событие с URL/ID и пропускает
  только это объявление. Нераспознанная выдача не выдаётся за пустой успех.
- Реальная CAPTCHA/страница входа дают событие `source_action_required`. В видимом
  браузере пользователь проходит проверку самостоятельно; после проверки
  `source_resumed` продолжает исходный переход. Ожидание ограничено и общим дедлайном.
  Запрет 403/429, TLS, истечение ожидания не обходятся.
- Прямое обращение к справочнику API HH удалено. Неизвестный регион определяется
  через видимый диалог сайта; нераспознанный регион не подменяется другим.
- В основной выдаче только актуальные оценки. Отдельно доступны количество и
  список неоценённых, причины и диагностические счётчики. Доступ ограничен
  активным пользовательским контекстом, включая `/api/search-diagnostics`.
- Семантическая классификация вопроса «почему не оценено» направляет ответ к
  сохранённой диагностике; не создаёт поиск и предложение его подтвердить.
  Полный список пропусков не передаётся модели для основного ответа.

Логическая схема SQLite, 11 опубликованных команд и четыре системных промпта
остались прежними. Диагностика — необязательные локальные файлы рядом с БД;
невозможность записать файл не отменяет результаты. У исторических задач без
диагностики приложение честно сообщает об отсутствии подробных причин.

## Настройки

В `config/v0.1.json` добавлены:

| Настройка | По умолчанию | Значение |
|---|---:|---|
| source.content_timeout_seconds | 15 | Ожидание содержимого страницы |
| hh.manual_action_timeout_seconds | 120 | Ожидание ручной проверки/входа |
| retries.max_structural_repairs | 1 | Исправления JSON/схемы, допускается 0 или 1 |

Общие ограничения: 100 кандидатов, 30 попыток нового анализа, 100 специализированных
LLM-вызовов, 600 секунд. Пропущенная детальная страница расходует лимит сбора;
попытка исправления структуры расходует LLM-бюджет, а не ещё одну вакансию.

## Проверка

Автоматические проверки: 133 основных теста v0.1, 11 браузерных и 9 проверок
сохранённого прототипа. Включены повреждённый JSON, исчерпание бюджета исправления,
повторный отказ одной вакансии, доказательства тегов с переносами строк,
неизвестный ID Resolver, отказ одного обновления оценки, пропуск нечитаемого
объявления, задержанная загрузка DOM, JSON-LD, ручное возобновление на тестовой
странице, выбор региона через UI и защита доступа к диагностике.

Проверки используют контролируемые ответы LLM и локальные страницы. Живой HH.ru
в облачной среде ранее возвращал `ERR_CERT_AUTHORITY_INVALID`; TLS не отключался.
Реального ключа DeepSeek в среде нет. Совместимость текущей разметки HH и качество
живой модели необходимо проверить на пользовательском Windows.

## Обновление локальной установки

Остановите приложение. Получите ветку `jobradar-v0.1` (`git pull --ff-only`, если
установка через Git) либо распакуйте свежий ZIP этой ветки. Сохраните `.env`,
`data/` и профиль `data/browser-hh/`; удалять БД не требуется. Если вы меняли
настройки, перенесите их в свежий `config/v0.1.json`. Запуск:

```bat
.venv\Scripts\activate
python -m pip install -e .
python -m jobradar serve --config config/v0.1.json
```

Обновите открытую страницу чата. При капче следуйте сообщению в чате и завершите
проверку в отдельном окне Chromium. После нового поиска раскройте
«Диагностика последнего поиска». Установленный отдельно старый код сам не обновляется.
