# JobRadar v0.1 — технический прототип

AI-ассистент поиска работы: диалог, несколько профессиональных профилей и поисковых
контекстов, HH.ru через Playwright, анализ DeepSeek, сохранённые карточки и персональные
оценки с объяснениями. Модульный монолит Python, локальный Flask-чат и SQLite.

Рабочая ветка — `jobradar-v0.1`. Ветка `jobradar-v2.2` и её старая БД не изменены.
[Отчёт о реализации и проверках](docs/v0.1-release.md).

## Запуск на Windows (CMD)

Требуется Python 3.11+. Из корня репозитория:

```bat
py -m venv .venv
.venv\Scripts\activate
python -m pip install -e .
python -m playwright install chromium
copy .env.example .env
python -m jobradar init-db --config config/v0.1.json
```

Команду copy выполняйте только при первом запуске, если своего `.env` ещё нет.
Впишите `DEEPSEEK_API_KEY` в локальный `.env`, затем:

```bat
python -m jobradar serve --config config/v0.1.json
```

Откройте `http://127.0.0.1:8765`. Для последующих запусков достаточно активировать
окружение и выполнить serve. На Linux: `python3 -m venv .venv`,
`source .venv/bin/activate`; остальные команды те же. Для видимого окна HH.ru
нужен графический рабочий стол. Внешние параметры — в `config/v0.1.json`.
Модель должна быть доступна вашему API-ключу; исходное значение `deepseek-flash`
сохранено из v2.2. Клиент использует режим без thinking для Tool Calling.

При первом запуске serve в `.env` автоматически добавляется `JOBRADAR_SESSION_SECRET`.
Сохраняйте его и cookie браузера: они позволяют восстановить активный контекст после
перезапуска. Незавершённое предложение ассистента требует нового согласия после
перезапуска процесса; профили, контексты, сообщения и результаты сохраняются в БД.

## Сквозной сценарий

1. «Создай профиль системного аналитика. У меня пять лет опыта, знаю SQL и REST API».
2. «Создай отдельный контекст для удалённой работы в Москве».
3. «Найди вакансии, изучи 10 объявлений».
4. «Больше интересуют компании EdTech; учти это в условиях поиска».
5. «Повтори поиск» или «Покажи результаты последнего поиска».
6. «Вернись в общий диалог»; создайте второй профиль и переключайтесь между ними
   свободными фразами. Профили и контексты выбираются через диалог.

Явные команды не требуют второго подтверждения. Предложения самого ассистента
исполняются после согласия. Известные сведения сохраняются; ответы и причины
несоответствия не должны выдумываться.

Поиск выполняется синхронно, без очереди. Браузер получает «Поиск запущен» до
планирования и сбора, затем прогресс и итог. Сохранённая подходящая карточка
используется повторно; изменение квалификации или критериев требует только новой
персональной оценки. При изменении сохранённого текста карточка переизвлекается.

## HH.ru

При необходимости входа/проверки пользователя выполните:

```bat
python -m jobradar hh-login --config config/v0.1.json
```

Войдите в открытом окне самостоятельно и нажмите Enter в терминале. Профиль
браузера остаётся в `data/browser-hh/`, в Git не попадает. По умолчанию
`hh.headless=false`; на сервере с установленным Chromium можно включить headless.

CAPTCHA, запрет доступа и ошибки TLS останавливают сбор с понятной причиной.
Ранее обработанные результаты сохраняются. Неизвестную географию нельзя молча
считать применённым фильтром: если HH не распознал регион, приложение просит уточнить его.
Географические коды берутся из встроенных основных регионов и публичного справочника
HH; вакансии собираются браузером. Постоянной перепроверки старых объявлений нет.

## Ограничения и конфигурация

- 100 исходных кандидатов на задачу, включая локальные и повторные обнаружения.
- 30 новых извлечений карточек, 100 специализированных LLM-вызовов, мягкий дедлайн 10 минут.
- 20 Tool Calls и до 24 логических обращений к Dialogue Agent на реплику.
- Таймаут DeepSeek 60 секунд; страницы источника 30 секунд; максимум 2 безопасных повтора.
- Значения предварительные, доступны во внешней конфигурации. Цель пользователя,
  лимиты обработки и количество показанных результатов — разные величины.
- Зарплата по умолчанию мягкая, опыт используется при оценке; отсутствие зарплаты
  не является автоматическим запретом. Известные география/формат применяются как
  жёсткие условия; неоднозначные сведения передаются на анализ.
- Неполное выполнение с результатами сохраняется как completed/is_partial с причиной.
  После остановки приложения незавершённые задачи восстанавливаются как прерванные.
- Сведения о неизвестных условиях не трактуются как доказанное несоответствие.

Не входят: автоотклики, мониторинг по расписанию, Авито, постоянная блокировка
вакансий/компаний, регистрация многих пользователей, PostgreSQL и административная панель.

## Данные и архитектура

Новая БД — `data/jobradar-v0.1.sqlite3`, без миграции старой `jobradar.db`.
Инициализатор не перезаписывает чужую схему. Секреты только в локальном `.env`.

- `src/jobradar/orchestration/` — связывание компонентов и сериализация ходов диалога.
- `dialogue/`, `llm/`, `tools/` — Dialogue Agent, транспорт, 11 утверждённых команд.
- `profiles/`, `storage/` — проверки владельца, частичные обновления, транзакции, SQL.
- `search/` — Search/Task Manager, ограничения, программный отбор и события.
- `sources/` — общий контракт и адаптер HH.ru.
- `analysis/` — Search Planner, Vacancy Analyzer и Tag Resolver.
- `web/` — Flask API, адаптивный интерфейс, локальные CSS/JS.
- `prompts/` — четыре неизменённых текста версии 1.0 из Confluence.
- `docs/reference/` — снимки исходных документов с версиями.
- [Выходные LLM-контракты](docs/contracts/README.md).

Один общий чат; карточки вакансий и теги общие, а оценки принадлежат контексту.
Входные схемы инструментов и логическая модель не изменялись. Новые источники
подключаются адаптерами и реестром обработчиков, без переписывания цикла диалога.
Минимальные структурированные логи выводятся в терминал без переписки, резюме,
сырого текста объявлений, cookies и ключей.

## Терминал и проверки

Диалог без браузерного UI: `python -m jobradar chat`. Выход — `/exit`;
восстановление сессии — `python -m jobradar chat --session ID`.

```bat
python -m unittest discover -s tests/v01 -v
python -m unittest discover -s tests/browser -v
python -m unittest discover -s tests -v
python -m pip check
```

Основные тесты не обращаются к HH.ru/DeepSeek. Браузерные тесты запускают Chromium
и локальный HTTP-сервер с контролируемыми ответами LLM/источника. Проверьте реальный
диалог с вашим ключом и HH-браузером на своём Windows: автоматические тесты
не подтверждают качество ответов живой модели или актуальность разметки сайта.

В облачной проверке реальный HH.ru был недоступен из-за
`ERR_CERT_AUTHORITY_INVALID` в Chromium. Проверка TLS не отключалась.
Реальных DeepSeek-вызовов без пользовательского ключа не было.
